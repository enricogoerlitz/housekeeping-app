# Edge Functions

Server side of the AI features and the map-link resolver (spec 0003, ADR-0009). Deno in the
Supabase Edge Runtime; unit-tested with vitest under Node.

| Function            | Input (contract)          | Quota     | Calls                                |
| ------------------- | ------------------------- | --------- | ------------------------------------ |
| `ai-assistant`      | `AssistantRequestSchema`  | `request` | Foundry LLM (structured output)      |
| `ai-search`         | `AiSearchRequestSchema`   | `request` | Foundry LLM (structured output)      |
| `speech-token`      | empty body                | `speech`  | Azure STS `issueToken` (short token) |
| `resolve-maps-link` | `ResolveMapsLinkRequest…` | none      | Google short links only, manual hops |

Every function: CORS allowlist → POST only → JWT verified with `auth.getClaims()` and
`role = authenticated` (the anon key gets 401) → body ≤ 64 KB and zod contract → quota via
`consume_ai_quota` with the caller's own client → work. Errors are `{ "error": code }`
(`ErrorReplySchema` in `packages/core/src/ai-contract.ts`). No service-role key is used anywhere;
all database reads run under the caller's RLS.

## Layout

- `<name>/index.ts` — `Deno.serve` entry, wires `liveDeps()` into the handler.
- `<name>/handler.ts` — logic with injected deps (`fetch`, `env`, `createUserClient`, `now`).
- `_shared/` — auth, CORS, errors, quota, Foundry client with retries, strict JSON schema helper,
  database reads (`context.ts`), map-link parsing (`maps-link.ts`, mirrors core `parseMapsLink`).
- `_shared/contract.gen.ts` — generated by `pnpm gen:edge`; never edit by hand.
- `deno.json` — import map for Deno (`zod`, `@supabase/supabase-js`, same pins as `package.json`).
  Source files use relative `.ts` imports and these two bare specifiers only.

## Commands

```sh
pnpm --filter @housekeeping/edge test        # vitest, no network
pnpm --filter @housekeeping/edge typecheck
pnpm gen:edge                                # after changing packages/core/src/ai-contract.ts
node scripts/edge-smoke.mjs                  # against a running local stack, see below
```

## Environment

Read by the functions (names only; values live in `.env`, never in the app):

- `FOUNDRY_API_KEY`, `FOUNDRY_OPENAI_BASE_URL`, `FOUNDRY_LLM_DEPLOYMENT` — LLM.
- `FOUNDRY_SPEECH_REGION`, `FOUNDRY_STT_LANGUAGE`, `FOUNDRY_STT_MODEL` (optional) — speech token.
- `ALLOWED_ORIGINS` — comma-separated browser origins, e.g. `http://localhost:8081`.
- `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEYS` (or legacy `SUPABASE_ANON_KEY`) — set by Supabase.

A missing variable fails the request with `500 internal` and logs the variable name.

## Serving locally with secrets

Recommended: `[edge_runtime.secrets]` in `supabase/config.toml` with `env()`. It hands the
functions only the named variables from the root `.env` (not `GOOGLE_CLIENT_SECRET` and the
rest), and it works both for `supabase start` and `supabase functions serve`. The alternative,
`supabase functions serve --env-file .env`, passes the whole file and needs a separate process.

Proposal for `supabase/config.toml` (not applied yet):

```toml
# [edge_runtime.secrets]
# FOUNDRY_API_KEY = "env(FOUNDRY_API_KEY)"
# FOUNDRY_OPENAI_BASE_URL = "env(FOUNDRY_OPENAI_BASE_URL)"
# FOUNDRY_LLM_DEPLOYMENT = "env(FOUNDRY_LLM_DEPLOYMENT)"
# FOUNDRY_SPEECH_REGION = "env(FOUNDRY_SPEECH_REGION)"
# FOUNDRY_STT_LANGUAGE = "env(FOUNDRY_STT_LANGUAGE)"
# FOUNDRY_STT_MODEL = "env(FOUNDRY_STT_MODEL)"
# ALLOWED_ORIGINS = "env(EDGE_ALLOWED_ORIGINS)"
#
# # The functions verify the JWT themselves (getClaims + role check). The gateway check adds
# # nothing (the anon key passes it) and would answer CORS preflights without a JWT itself.
# [functions.ai-assistant]
# verify_jwt = false
# import_map = "./functions/deno.json"
# [functions.ai-search]
# verify_jwt = false
# import_map = "./functions/deno.json"
# [functions.speech-token]
# verify_jwt = false
# import_map = "./functions/deno.json"
# [functions.resolve-maps-link]
# verify_jwt = false
# import_map = "./functions/deno.json"
```

`EDGE_ALLOWED_ORIGINS` would be a new line in `.env.example` (e.g. `http://localhost:8081`).
Then `pnpm exec supabase start` (or `pnpm exec supabase functions serve`) serves them on
`http://127.0.0.1:54321/functions/v1/<name>`.

## Smoke test

`scripts/edge-smoke.mjs` calls every function with the anon key (expects 401) and with a user
JWT from a password sign-in of a seeded test account:

```sh
ANON_KEY=<legacy anon JWT from `supabase status`> TEST_EMAIL=… TEST_PASSWORD=… \
  node scripts/edge-smoke.mjs
```

The AI calls reach Foundry for real (or a mock behind `FOUNDRY_OPENAI_BASE_URL`) and count
against the test account's daily quota.
