## Arbeitsweise (so hat Enrico es gewollt)

- **Ablauf je Feature:** Spec (deutsch) → bauen mit Tests (rot zuerst) → selbst durchklicken (Desktop im Browser,
  Handy im iPhone-Simulator) → PR nach `develop`, nach grüner CI squash-mergen → nächstes Feature.
- **Am Ende einer Runde:** einmal Security-Check über den Diff seit dem letzten Release-Tag, volle e2e-Suite in GitHub
  (`gh workflow run e2e.yml --ref <branch>`), Fixes, Vorschau (`gh workflow run preview.yml --ref develop`), dann
  Release – nur mit Enricos ausdrücklicher Freigabe (`gh pr create --base main --head develop --title
"chore: Veröffentlichung"`, Merge-Commit; `release.yml` macht den Rest).
- **Kein e2e je Feature**, keine Sicherheitsprüfung je Feature; Negativtests (fremder Haushalt, abgemeldet,
  ungültige Eingaben) gehören aber in jedes Feature.
- **Enricos UX-Maßstab:** Beschriftungen passen zum Zustand; kein doppelter Knopf; Hauptaktion im Fensterkopf (Handy
  oben rechts, Desktop unten rechts); keine fetten Knopfreihen; Fenster und Tastatur bewegen sich in einem Zug, nichts
  springt; Chat-UI orientiert sich an den mobilen Apps von Gemini/ChatGPT.
- **Kleine Änderungen** testet Claude/Copilot selbst und gibt Bescheid; Enrico testet die großen Sachen in der Vorschau.
