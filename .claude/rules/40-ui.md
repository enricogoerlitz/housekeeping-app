# UI

The look and feel is defined in `docs/design/DESIGN.md` (created by the design spec). Until it
exists, keep screens unstyled beyond the bare minimum and do not invent a visual language.

## Building screens

- Use tokens and components from `packages/ui`. No hard-coded colours, font sizes, spacing or
  radii in feature code. If a component is missing, add it to `packages/ui` first.
- Load `expo-native-ui` for native controls and platform conventions, `expo-router` for
  navigation, `animate-expo` / `gestures` for motion and drag interactions.
- Every screen works on **iPhone, iPad, Android phone and a desktop browser**. Use the available
  width on iPad and desktop (two columns, max content width) — no stretched phone layout.
- Every list and screen has designed **empty, loading-from-cache and offline** states. Offline is
  normal, not an error: reading and checking items work, edit actions are disabled with a short
  hint ("Offline – zum Bearbeiten brauchst du Netz").

## Feel

- Touch targets at least 44 × 44 pt. Primary actions reachable with one thumb.
- Respect Dynamic Type / font scaling, dark mode, reduced motion and safe areas.
- Haptics for meaningful moments only: checking off an item, completing a reorder, a destructive
  confirmation.
- Animations run on the UI thread (Reanimated) and are interruptible.

## Copy

German, short, friendly, no technical terms ("Wird synchronisiert …" rather than "Upload queue
pending"). Strings live with their feature; no hard-coded copy in `packages/ui`.

## Before calling UI work done

Run `/ui-verify` and look at the screenshots. Run `impeccable` critique on new screens and
`review-animations` on new motion. Fix what they find or record why not.
